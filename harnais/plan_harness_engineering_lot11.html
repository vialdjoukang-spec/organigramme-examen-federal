0 Qu’est-ce qu’un harness ?

Un harness (harnais) est l’ensemble des outils autour de l’agent (le bot qui rédige), pas l’agent lui-même. Sans harness, l’agent relit trop, invente, oublie, gaspille des jetons (unités de calcul du modèle) et s’épuise. Avec harness, chaque étape a un contrat (règle écrite : ce qui entre, ce qui sort, ce qui est interdit).

Image simple. L’agent est le chirurgien. Le harness est la salle : check-lists, instruments stériles, chronomètre, alarme si un appareil tombe. Le chirurgien décide ; la salle empêche les erreurs répétables.

Pourquoi « engineering » (ingénierie) ?
Parce que chaque pièce a une entrée (INPUT), une sortie (OUTPUT), un échec prévu et un chemin de secours. Ce n’est pas une liste d’outils posés au hasard : c’est un circuit.
Objectif chiffré pour un lot
Un agent + son harness gère seul un lot (SSP + 10 DX) : recherche → Appel A → Parties B → audits → dépôt HTML 90–200 Ko, sans s’épuiser et sans inventer de dose.

1 Les 4 pièces déjà disponibles chez Vial

Le harness installé ici réutilise le matériel déjà en place (Thunder → Bitender → Grok Bot), sans inventer une stack nouvelle.

Script 1

Script 1 (outil déterministe d’extraction / budget) : lit un morceau ciblé d’un gros fichier, jamais le fichier entier. Chez Vial : tools/arsenal/extrait.py + tools/budget.py.

Contrat Script 1

ENTRÉE (INPUT)

Identifiant SSP/DX ou chemin ; option partie N ; plafond de lignes.

SORTIE (OUTPUT)

Extrait compact (texte/JSON) + métadonnées ; code retour 0/≠0.

Interdit : renvoyer app_v2.html entier (~440 Ko).

Script 2

Script 2 (outil déterministe d’assemblage / PR / CI) : injecte le lot, ouvre la PR, attend la CI. Chez Vial : tools/arsenal/lot.py, pr.sh, ci_attente.sh, audit_diff.py.

Contrat Script 2

ENTRÉE

Artefacts validés (JSON/HTML lot) + message PR + branche.

SORTIE

URL PR ; statut CI une ligne ; diff d’audit borné (--max).
MCP

MCP (Model Context Protocol = serveurs d’outils connectés que l’agent appelle sans quitter le chat) : Drive, GitHub/Origin, Calendar, etc. Ils apportent fichiers et actions externes.

Contrat d’un appel MCP

ENTRÉE

Nom d’outil + arguments typés (fileId, query…).

SORTIE

JSON/texte utile OU erreur explicite → bascule fallback (§E10).
Automates

Automate (script déterministe sans LLM) : contrôles mécaniques (doses vs liste AIPS, sources datées, infobulles, chaîne lésion→PEC). Galien (revue clinique) ne lit que le diff + signalements.

Contrat automate

ENTRÉE

Fichier HTML/JSON du lot + liste de règles.

SORTIE

Rapport pass/fail + liste d’anomalies ; zéro prose libre.
Bracelet

Bracelet (couche permanente d’optimisation jetons/outils, greffée à chaque session) : catalogue + script bracelet_suggest.py qui suggère l’outil avant crawl, gros volume, cache, mémoire, budget. Source : /home/box/agent-data/bracelet/BRACELET_OPTIMISATION.md.

  • Mémoire : Mem0, Graphiti

  • Orchestration : APScheduler, Celery

Glossaire express (toujours répétable)

  • Agent : bot qui rédige/audite.
  • Harness : harnais d’outils autour de l’agent.
  • Jeton : unité de coût du modèle.
  • Script 1 / 2 : programmes locaux déterministes (extrait vs assemblage/PR).
  • MCP : serveurs d’outils connectés.
  • Automate : script sans LLM.
  • Bracelet : couche permanente d’optimisation.
  • Contrat : ENTRÉE / SORTIE / échec / interdit écrits.
  • SSP : situation de départ PROFILES.
  • DX : diagnostic différentiel monographie.

FAQ harness (cliquable)

Le harness remplace-t-il l’agent ?

Réponse courte : Non. Il contraint et outille l’agent.

Le harness ne diagnostique pas et n’écrit pas la physiopathologie à la place du clinicien-agent. Il garantit que chaque phrase clinique reste attachée à une source ouverte, que les fichiers respectent 90–200 Ko, et que les outils coûteux ne tournent pas en boucle. L’agent reste responsable du fond ; le harness est responsable du circuit.

ENTRÉE de la question : doute opérateur. SORTIE : règle opératoire une phrase + lien interne.

Puis-je sauter le bracelet ?

Réponse courte : Non sur fetch volumineux ; oui sur rename trivial.

Sur une tâche triviale (renommer un dossier, lire un CSV de 20 lignes), oui. Dès qu’il y a crawl, PDF long, guideline, ou répétition, non : lancez bracelet_suggest et appliquez au moins un outil de filtrage ou de cache. C’est la règle « permanent » du MD bracelet.

ENTRÉE de la question : doute opérateur. SORTIE : règle opératoire une phrase + lien interne.

Où vivent les lots non finis ?

Réponse courte : GitHub « lot en cours de production/ ».

Décision owner 25.10.2026 : racine GitHub visible « lot en cours de production/LOT_xxx/ ». Pas de lots-acheves sur GitHub. Cela évite les chemins profonds flash/vague1/…

Où vivent les lots finis ?

Réponse courte : Drive LOTS_Finaux avec statut uniquement.

Uniquement Drive « LOTS_Finaux avec statut ». Audité ou non, dès que A+B sont complets (11+11 chapitres), le lot quitte GitHub en-cours pour Finaux.

Que faire si V7 et ARSENAL divergent ?

Réponse courte : V7 prime sur le contenu lot ; ARSENAL prime sur l’économie de jetons outils.

Pour le contenu médical et le format HTML, V7 gagne. Pour la manière d’ouvrir les fichiers du repo app et d’économiser les jetons d’ingénierie, ARSENAL gagne. Le bracelet s’applique aux deux.

Comment savoir qu’un contrat est respecté ?

Réponse courte : Sortie machine-lisible + code retour + log une ligne.

Chaque script doit pouvoir être appelé en CI. Si la SORTIE n’est pas parsable ou si le code retour est non nul, le gate dépôt reste fermé. Les contrats de ce plan sont la spécification.

Qu’est-ce qu’un jeton ?

Réponse courte : Unité de coût d’entrée/sortie du modèle.

Quand l’agent lit ou écrit du texte, le fournisseur de modèle compte des jetons. Moins on recolle de bruit (menus web, logs, fichiers entiers), plus on garde du budget pour la monographie utile.
